# Changelog

## Unreleased

- **Galleries for single parts of a site:** Footer Design and CTA Gallery for a footer or a call to action, and Recent's motion listing and Codrops demos for motion, only when the brief asks for motion examples. `sources.md` says how to read each one's cards and what to keep. Behance stays out of the picker: it refuses scripts.

## 0.12.2 — 2026-11-21

- **A shot can be a picture's URL.** `moodboard.mjs` shows an `https://` shot from that address instead of dropping it as missing, and `families.mjs --board` writes it into `board.md` as it is (it was turned into `https:/…`). A library exported with its pins' addresses makes a moodboard with no pictures copied.

## 0.12.1 — 2026-11-21

- **More galleries for the moodboard:** Minimal Gallery and httpster (browsed by tag, since neither has a search a script can use) for sites, and Fonts In Use (by subject tag or format; its search is off-limits to scripts) for the far reference: print, signs, packaging, with the typefaces named. `sources.md` says how to read each one's cards, and which galleries stay out of the picker and why (Land-book, Lapa Ninja, landing.love and siteinspire refuse scripts; One Page Love asks for its API key; Best Website Gallery's search finds only names).
- New skill, `framework-skills`, at Architecture: it reads the stack from the ADRs and manifests (`pubspec.yaml`, `package.json`, `Cargo.toml` and others), searches with `skills find`, prefers the framework's own published skills and then the most installed, reads each one, and proposes the few this project needs with a reason for each. On yes it installs them with `longbeard add`. The router reruns Architecture for a new stack, so a project that turns to Flutter later gets the offer then. It replaces the old "At Architecture, a framework skill." hint, which named nothing.

## 0.12.0 — 2026-11-21

- **`image-to-code` is no longer an add-on.** It generates its own design images and builds from them, which is the agent's taste, not the board's. A picture you like goes on the moodboard instead, and a Figma file you were handed goes to `figma-design-to-code`. `update` removes it from a project that has it, unless you edited it.
- **`links.mjs` scans, it no longer walks.** It opens every page in the prototype's folder, not only those a click reaches, and says what is broken, goes nowhere or has no way on, with the stand-ins to supply. Whether a person reaches each key screen is the flow walks' job: `--expect`, the unreached list and the click counts are gone, and so is the eval's "every key screen reached" check, which failed on a checkout behind an empty basket.
- **A colour they liked wins over contrast.** It is never stepped lighter or darker to pass. The pair is fixed with what else the screen has (the other colour, large text, a crop, the colour moved to a fill); when nothing fits, the colour stays with a warning on the sheet, in the identity options and in `DESIGN.md` (`WARN liked, kept`), which `design-check` and the eval report as a warning, not a block.
- **`rules.mjs` counts a round only when the same page changed:** fix after every run. A first run of another state of a screen (`?menu=open`, same `--screen`) is part of the round it is in, so checking two states no longer uses up both rounds before anything is fixed.
- **Cheaper judges:** the not-a-copy check is one judge for the whole round, the five-second viewers see every key screen in turn instead of three new viewers per screen, and judges run on a smaller model where the agent lets you choose one. The critic and fix loop stops after two passes, and a stand-in picture is not a spot to fix.
- `design-direction`'s full build (critique and fix) moved from `grid.md` to `full-build.md`, read only once they pick, so the first round reads less.
- The README's Design stage is a short paragraph; the kit lists the skills.
- **`screen-contrast.mjs` judges text only where it shows** (`clip-path`, `clip`, overflow, and a later copy of the same text in the same box), so a knockout label no longer reads as 1:1. It also cleans up Chrome's profile folder in under 5 s, where it used to wait out 21 s of retries and leave the folder behind. The full test run drops from about 6 minutes to under 2.
- The design eval says which run to use when: `--from` for a change to how screens are built, a full run before a release.

- The tag for what a picture shows is `shows`, not `subject`: "subject" is the product's own world in `design-direction`. A header or a stored profile that still says `subject` is read as `shows`.
- **Readings record motion, a pasteable finish and the kind of picture, and the chosen screen carries them through:** `motion` is read for the lead and the references a pick is built on (`not seen` for a still), a screen may borrow a finish like any element, and a picture kind is recorded and never borrowed. `design-direction.md` gets `motion:` and `finish:` lines, `DESIGN.md` a Finish line and `motion/` rows, the prototype builds from them and says which reference's motion it replayed, `design-check` checks the build against them, and `design-figma` builds a static finish and notes the motion it cannot carry.

- `measure.mjs` lists a live page's motion (each transition and animation with its property, time, delay, easing, loop or once, what it is on and its trigger, read before animations are ended) and its finish (shadows, filters, blends and textures with the share of the screen they cover), and says how many stylesheets it could not read, in new `motion`, `finish` and `unread` keys that leave the rest of the output as it was.
- `measure.mjs` also lists motion a script makes (an `element.animate` with its own time and easing, values written frame by frame in a short watch at load and while the page is scrolled one screen, with time and easing "not seen", and a playing canvas or video with its cover of the first screen), says in new `motionMore` and `finishMore` keys how many entries its caps left out, and counts a canvas it may not read in `unread`.
- **The reason is caught when it is felt:** a liked tile on the picker opens a small note for what you like in it and why, copied out beside that pick, then written on the keep's card as a `like:` line, shown and pre-filled on the board, and not asked again at `design-direction`.
- **`DESIGN.md` carries its tokens in the published DESIGN.md format** (new): `tokens.mjs` writes them as front matter from the tables, which stay the source, so another tool can take the design without Long Beard; `--check` and `design-check` docs mode say when they disagree.
- `tokens.mjs` also reads an older `DESIGN.md`'s spacing and radius bullets (and says which line it cannot name), writes a `primary` inside each theme group, and `eval/design/score.mjs` checks that the token block agrees with the tables and that a finished run lists its stand-ins.

- **`design-direction`: the critic loop can end, and the text is about 400 words shorter.** The loop stops when only small spots are left or after three passes, and the rest goes on the sheet as known faults. The critic also asks what on the screen exists only because of this product (an empty answer is a fault), "not a copy" is a yes or no, and pictures, tones and moves are spread when the round is planned. The subject is a card on the board, liked with a why, and what they like in it may return in another form. `design-moodboard` asks for one far reference when the board is only screens.

- **Live controls on the chosen screen** (new, in `design-direction`): the screen's page can show type scale, line spacing, accent strength and corner radius as sliders, each limited to the range the references on your board measure (a control the board gives no range is not shown), and Copy gives back the values for the agent to record in the screen. Open it with `?controls`; a capture never shows it.
- `design-moodboard` groups a search's candidates into measured families before the picker opens (`group.mjs`, using `measure.mjs` and `families.mjs` on thumbnails read from their URLs and never saved), the picker shows them grouped with each group's size (`picker.mjs --families`; without it the page is unchanged), and a search with fewer than four families of real size is widened before anyone picks.
- **Graphics** (new): a poster, a card or a social post goes through the same design steps as a site or an app. `idea` writes a short brief for a piece (its facts and format), and each design skill a graphic changes has a `references/graphic.md`, read only for a graphic and pointed to by one line in its gate, so a site or an app run is unchanged. The design rules gain a Graphics list, and a graphic's run ends at the exported Figma frame. Proved on a poster; a card and a post follow the same path. Delivered in RGB as PNG and PDF, never CMYK.

- **Design only** (new): `npx longbeard init --design`, or the question "Design only, or the whole pipeline?" on a first `init` in a terminal, installs `idea`, the `design-*` skills, `design-check` and the Figma skills the design stage uses, with an `AGENTS.md` block that has just the Idea and Design stages. `beard-lock.json` records the choice and `update` keeps to it. `init --full` or `update --full` adds the rest, and leaves your design docs as they are. `design-check`'s build mode says it needs the build stage.

- `design-check` gains `rules.mjs`, shared with `design-prototype`: it opens a page headless at desktop and phone width and prints the hard rules a browser can measure in the findings table, each tied to its rule (sideways scroll, small targets, inputs without a visible label, a focus that shows nothing, placeholder copy, clipped text). Text cut on purpose carries `data-crop` and is skipped; it never checks overlap, collision, alignment or empty space. A check that could not run is "not checked".
- The fix loop is enforced by that script: it counts rounds per screen and says "rounds used up" when the limit is reached, a waiver needs a reason and stays listed, "ship it as it is" is recorded with the person's words, and a run that cannot start blocks once and then lets the build go on. State is in `.longbeard/design/rounds.json` and `waivers.json`.
- Copy is made from facts the product has: `design-content` fills a fact sheet from the brief and the design brief before any sentence (an empty field shrinks or drops its section, and the doc lists what you must supply), `design-prototype` does the same when it drafts without that doc, and rule 11 gains checks for one use of each device per screen, no invented numbers, names or quotes, claimed sincerity, and a voice that would not suit another trade.

Design is now a family of small skills, each with one job and one doc, instead of two long ones. You run only what you need, each step asks little, and a long run no longer drifts. [How it flows](assets/design-flow.png).

- **`design`** is now the way in: it reads your project and suggests the next design skill, and why. It never runs one for you. It offers `design-families` only for a board over about 60 references, and a gap search for one under about 8.
- **`design-brief`** (new): a studio's questions in one message, one read-back, written to `docs/design/design-brief.md`. It asks: what the first screen must make someone think and do; three words it should be and one it must never be; personality on seven scales (quiet–loud, type-led–picture-led, plain–rich, warm–cool, serious–playful, classic–new, airy–dense), with suggestions that lean off the middle; feel and never; who to stand apart from and how far from the category; what is fixed, including new brand or refresh and AA or AAA; and motion, picked from options (how much, what drives it, its character and its moments) instead of one word, which `design-prototype` builds and nothing beyond. The read-back shows the voice with a sample line, so it is confirmed before any copy is written in it. Every answer is read later:
  - the moodboard search puts the personality into its queries, leaves out what looks like the products to stand apart from (when far from the category is the ask), and drops what is plainly the never;
  - the direction's table adds what the eye sees against the never, the words and apart from: notes to choose by, never cuts; a reference you like that the brief rules out is raised before building, and the brief wins;
  - `families.mjs --sliders` takes `dense`;
  - the accessibility level sets every contrast check (`contrast.mjs --level AAA`, `screen-contrast.mjs --min 7 --large 4.5`), and `DESIGN.md` records it, with its density and motion;
  - `design-check` checks the level, the motion line, and whether a screen could be mistaken for the products to stand apart from;
  - the person who also has to say yes is asked at the direction, the identity board and `DESIGN.md`.
- **The five-second check** (new, in `design-direction` and `design-prototype`): three fresh agents who know nothing of the product see only the screen and say what it is, who it is for, what they would do first and how it feels; that is set against the design brief's takeaway. A miss is fixed only with the touch-up's own means (the headline, the action, rank), and a check with two or three real people is offered once.
- **Walking the prototype** (new, in `design-prototype`): `links.mjs` clicks through it from the first page and says each broken link, each link or button that goes nowhere, each page with no way on, each key screen no click reaches, and how deep each page is. Then a fresh agent tries each of the brief's flows from its goal alone, and where it gets lost is fixed.
- **`pace: quick`** in the design brief, for an internal tool or a first version: their references as they are (or one contact sheet to name six to ten from), one round of screens, the screen's type and colours as the identity, no options in the prototype unless asked, and no optional skills. States, contrast, the walks and the five-second check stay.
- **Phone or desktop first:** the design brief asks where the first screen is mostly seen. A site seen mostly on phones is built at 390. Before the chosen screen is recorded, the agent looks at it at the other width and says one line only when the composition depends on the width.
- **`design-moodboard`** (new, from `design-direction`): reads your board (big Figma boards included: your captions, tags and stars, shared image sheets downloaded once and cropped locally) and fills only its gaps, or runs the picker search. Each keep gets its move in words.
- **`design-families`** (new, optional): sorts a big board into looks, measured, tagged and checked by eye, and, for a Figma board, writes a `Families` page beside yours without touching it. You take one or two.
- **`design-direction`** now works from your references the way a designer works from a board. You are the designer: you pick the references, say what you like in each and why, and choose the result; the agent adds nothing that is not on your board. It starts with three or four pictures of your product's own subject, yours or licensed stand-ins from Wikimedia Commons (`pictures.mjs`: a few, never a bulk search), plus a few colours proposed from them (`subject-colours.mjs`). Each reference you lead or like is read and measured: layout, type sizes, spacing, palette, picture treatment, how much text it carries, its devices (`measure.mjs` now reads the type in a picture, and `fonts.mjs --shape` finds the nearest free face by its measured shape). Then eight screens, each one reference rebuilt faithfully with your content, then changed by one or two things borrowed from your other references: what you like is what is borrowed, and your why decides where it may go ("the only contrast on a quiet page" goes only on quiet pages). Five principles decide every case. The first round is quick: each screen is built once by a fresh agent (the base translated and measured against it with `layout-diff.mjs`, which also draws the two side by side and overlaid, then the moves), with no critic loop and no device close-ups, so it arrives in minutes and the sheet marks each screen rough or full. The full build (a builder, a critic who sees only the pictures and lists every spot less finished than its reference, a fixer for those spots only, at most three times, every version kept) runs only on what you pick: more of one, a mix, or the screen you lean to. The sheet is drawn only when `screens.json` records every screen's state (built, critiqued, fixed, or failed and why); with no fresh agents the agent does the jobs in turn and says the round is weaker. Then the round is checked: not a copy, as varied as the board, contrast (a failure blocks the sheet), faults, picture casts (`picture-cast.mjs`). Each screen carries what its reference carries; the rest of the content waits for `design-prototype`. You pick, ask for more of one, a mix, or a fresh round as often as you like. Then a light touch-up pass fixes only contrast, a missing item or action, and anything plainly broken, shown before and after. Overlaps, collisions and crops are the look and stay.
- **README and PRODUCT** say it plainly: Long Beard does not claim taste. It brings an art director's process, and your taste comes in through your references, your likes and your choices.
- **The design eval** gains `screens.mjs` (tiny and clipped text, contrast, and text against the reference's slots), read by `score.mjs`; `run.mjs --from` rebuilds only the screens from a finished run's inputs, and `--fixture` runs on another board (a second board of seven references is included).
- **`design-identity`** (new): refines the chosen screen's type and colours on that screen, from close options you can trace (as built, measured neighbouring faces, even colour steps, your other references, your subject's pictures, what you own), one refinement, then the identity board, a type and colour specimen with squircle swatches. It replaces the bento board, and `design-figma` puts it on the Figma Cover. The identity is set back on the chosen screen through its `LOOK`.
- **Stand-ins are marked and listed** (`design-content`, `design-direction`, `design-prototype`): a stand-in picture or a fact the brief does not give (a price, an hour, a number, a name) carries `data-standin="picture"` or `"fact"` in the markup. `links.mjs` lists them while it walks the prototype, and flags a stand-in picture with no mark. The list is shown with the prototype, written into `DESIGN.md` under Still to supply, noted on the Figma frames, and a stand-in that reaches the build is a hard finding in `design-check`.
- **`design-prototype`** (from `design`): the first screen finished, the other key screens prototyped in one go with drafted copy and the product's own pictures, forks offered, then `DESIGN.md` on your yes. "Beat a plain agent" is gone.
- **`design-figma`** (from `design`): tokens, the identity board, components, screens and states, each checked and marked Ready.
- **`design-content`** (new, optional): what each screen says and shows, drafted for you to correct, and the full picture list, with stand-ins found only for the gaps.
- **`design-wordmark`** (new, optional, after the identity): a mark made from your type, judged where the name sits in your chosen screen, added to the identity. No mark is a fine answer.
- **`design`** says once, at the start, where the design steps end: `DESIGN.md` and a Figma file of your own to keep working in. **`design-figma`** ends by saying what that file holds. The README has a new section, Who it is for.
- **`design-check`** gains a docs mode: the design docs must not name a reference, link one, or point into the working folder.
- **Files:** the design docs live in `docs/design/` (`design-brief.md`, `design-moodboard.md`, `design-families.md`, `design-identity.md` and `.html`, `design-direction.md`, `design-content.md`) and are committed: they describe the style, never the source. Captures, pickers, profiles, grids and prototypes live in `.longbeard/design/`, gitignored. Nothing writes to `design-exploration/` any more.
- The router has one Design row (`design` → Figma) instead of Direction and Design.
- Removed with the old flow: `deal.mjs` and the grid page; script copies no skill uses.
- Script fixes carried over from the earlier method: `capture.mjs` fails on a page it cannot reach and dismisses more consent banners; `measure.mjs` reads a screen inside a presentation frame; `families.mjs` splits a bin far bigger than the rest and takes `--only`; `screen-contrast.mjs` samples under every text box; `fonts.mjs --kind` overrides Google's category; `colours.mjs` keeps the screen's ink where it reads; `screen-contrast.mjs` measures outlined text by its stroke.

**If you already ran `init`:** run `npx longbeard update`. The new skills install and the old `design-direction` and `design` are replaced. An existing `design-exploration/` folder is left alone. A project with a `DESIGN.md` is unaffected; a project mid-direction starts again at `design-brief` (its answers are quick to give again) or at `design-identity` if you write the design brief by hand.

## 0.11.2 — 2026-11-18

- `design-direction` asks whether you already have a moodboard: a Figma link (file, page or section), a folder of images, or links. If you do, it is the base. The agent reads the board and checks whether it is enough: three distinct anchors, and every part of the product covered. If it is, there is no search. If not, it says what the board lacks and offers a search for only that (a pool of 20 to 60, one picker round), or the full search when the board is too thin for even one direction. It opens the shortlisted references at full size (from Figma, the original upload, GIFs included, with motion recorded as frames), and proposes 3 directions as small boards of 6 to 8 references. Each direction is anchored on one reference's move, kept whole, with moves from other references combined around it and never averaged, and never one reference's whole concept. The search, the picker and the board of 100 stay for people without a moodboard.
- `design` keeps the direction's reference shots open while prototyping, for the finish text cannot carry: type character, spacing, texture. They rank below the design rules and are never copied. A reference that moves is replayed before the part it inspires is prototyped: its frames, and its live page recorded again, so the prototype's motion has the same feel.

## 0.11.1 — 2026-11-17

- The brief has a **Position** section: what the product is up against, the one concrete thing it is remembered for, and its personality. `idea` recommends it from what people do today instead, and `design-direction` builds `ownable`, `voice` and `leave` from it, so the look aims at being distinctive rather than guessing.
- `design-direction` keeps about 100 references by default instead of 12, spread across the whole site (home, navigation, index, case study, article, blog, photography, motion) or an app's key screens, and reaches back to older award winners. The pool and the second round grow to match, and a keep is the page that shows its part, not just the home page.
- The moodboard is a picker. Tiles are grouped by part, each with Lead (one per part), Like, No and a note, and a copy-out for the chat. `direction.md` lists its references by part. Recorded motion plays on the tile.
- `design` lays the approved look out as a bento board in Figma before any component: the name in the display face, the type styles, the colour tokens and themes, real pictures from the prototype, a line in the voice, a key screen, the ownable, and a big number if the product has one. Every tile is bound to the tokens, and they say yes to it before the screens are built.
- `capture.mjs` waits out loaders and intros (no loader covering the screen, not one flat colour, the network quiet; up to 15 s on the web, 2 s locally, `--wait` to change), turns down cookie banners without removing the page around them, and keeps the first screen when a canvas page comes back blank at full length. `--frames N` records timed frames of an intro, a scroll (`--scroll`) or a click (`--click`), and `--click` alone captures the screen after a click, such as an open menu. Local pages are left as they are (no consent clicks), and a local file can be captured up to 30000 px tall, so a moodboard of 100 fits. WebGL and intro-heavy sites came back blank before, and transitions could not be judged from stills.

## 0.11.0 — 2026-11-15

- `design-direction` calls itself the inspiration step, and its wording and the README's say so plainly.
- A project that joins with some stages done no longer gets sent back through them. The router starts Direction only when there is no `DESIGN.md`, and `idea` offers the first stage still to do.
- The router and our skills say to type a command like `/grill-with-docs` when the agent cannot start that skill itself, instead of promising to start it on yes.
- `idea` reads any file at the root that describes the product, keeps stack and architecture out of the brief, and asks what happens to a document that now covers the same ground.
- `design` checks and marks a screen Ready when a feature touches it, for projects whose frames were never marked. `design-check` reports a screen with no Ready frame as "not checked".
- The README says how to catch up a project you already have.
- Themes are Figma modes on one colour collection, and each screen is built once. `design` builds them that way, and `design-check` flags separate colour sets or a frame per theme, flags unbound colours as hard, and checks each theme. A screen with a copy per theme becomes one frame when a feature touches it.
- Frame names take a device when the layout differs: `<screen> · <device> — <state>`.
- Empty, loading and error are required only when a person can reach them. A state nobody can reach is recorded under Decisions in `DESIGN.md`, with the reason.
- `design-check` finds states by what a frame shows, so state names can be descriptive.
- When `init` or `update` cannot list a kit from GitHub, it says why: the network error (like `ENOTFOUND`), the HTTP status, a reply that is not JSON, or a kit with no skills. Before, a failed connection said only "Check the network".
- `design-direction` keeps Dribbble shots people valued, not just new ones. `dribbble-cards.mjs` sorts by likes, drops shots under 100 likes (`--min-likes` changes that), and prints each shot's designer. The skill ranks by likes rather than page order, compares likes between shots of a similar age, drops dated shots, and keeps at most one shot from a studio that posts near-identical concepts.

- `design-direction` lets you steer the look. It searches wide (40 to 80 candidates from every source you chose) and cuts only what is off-topic or below the source's quality floor, not for taste. The new `picker.mjs` shows that pool as one page where you mark each like or no and add why, then copy your picks into the chat. The agent reads back what your likes and noes share, runs one sharper second search from that (same designer, same tag, the same pattern on other sources), and builds the moodboard from your likes. What your noes share goes into `leave`. `dribbble-cards.mjs --picker` prints rows for it, and `sources.md` says where each source's cards keep their title, thumbnail and link. siteinspire is no longer ticked by default: it refuses scripted requests, so it cannot be in the picker.
- `init` asks which add-ons you want, in the same kind of list as the agents. `--all`, `--skill <name>` and the new `--no-addons` answer for you and skip the list. `update` never asks.
- New add-on: `modern-web-guidance`, from the Chrome team with Edge, Firefox and MDN. It steers HTML, CSS and client-side JS toward current browser APIs. It is ticked in the `init` list, and a first `init --yes` takes it. It looks each guide up with `npx`, so it needs the network; untick it, or pass `--no-addons`, if that does not suit the project. A project that already ran `init` takes it with `npx longbeard update --skill modern-web-guidance`; the agent does not offer this one.

## 0.10.0 — 2026-11-04

Long Beard is now a pipeline: Idea → Direction → Design → Architecture → Plan → Build. Each stage writes one file the next one reads (`docs/brief.md`, `design-exploration/<slug>/direction.md`, `DESIGN.md` and Ready Figma frames, `GLOSSARY.md`, specs and tickets, one PR per spec), and ends by offering the next. The `AGENTS.md` block is a stage table the agent reads to know where it is, under 200 words.

- New: `idea` grills an idea, or an existing repo, into a one-page `docs/brief.md`. `design` asks about colour and type, prototypes the brief's key screens in plain HTML, writes `DESIGN.md` in one go when you approve one, and builds the screens in Figma from it, with their empty, loading and error states. `design-check` checks a Figma screen, or a built one against its Ready frame, using the new design rules (`rules/design-rules.md`): hard findings block, soft ones are reported, and it never redesigns.
- `design-direction` replaces `design-reference-hunt`. It finds ideas and patterns, never colours or type, which are chosen in `design` on rendered screens. Cards are link, shot, pattern and why. It writes `design-exploration/<slug>/direction.md`, a proposal, instead of `.design/board.md`, and no longer asks to write `DESIGN.md`. Its sources are only ones that work without a login: Awwwards, siteinspire, Recent, Dark Mode Design, Dribbble, Muzli, and Wikimedia Commons. It brings back 12 references by default.
- `design` replaces `design-md`. An existing `DESIGN.md` stays official; `design` adds to it for a feature and never rewrites it without your yes.
- Matt Pocock's skills are a kit again: all 27, including `grill-with-docs` (Architecture) and `pr` (Build).
- Figma's `figma-use`, `figma-generate-library` and `figma-generate-design` join `figma-design-to-code`. Figma is required for a project with a UI.
- Gone: ponytail (all of it), `premortem`, `design-taste-frontend`, `design-md`, `design-reference-hunt`.
- `animate`, `jury` and `web-design-guidelines` are add-ons now, with `security-audit` and `image-to-code`. The agent offers one when it is needed. `init` and `update` take one with `--skill <name>`, or all with `--all`. An add-on you already have stays and keeps refreshing.
- `update` removes any skill the catalog or its kit no longer lists, not only kit skills. One you edited stays unless you pass `--force`.
- `capture.mjs` takes `--width` (below 768 it shoots a phone at 2x), `--cookie` for a page behind a login, and `--strict`, which exits 1 when the page lands at another address.

People who already ran `init`:

```bash
npm install --save-dev @jonandev/longbeard@latest
npx longbeard update            # installs the new skills, removes the dropped ones you did not edit
npx longbeard update --force    # only if update listed dropped skills it kept because you edited them
```

`.design/` is no longer read. Keep it for your own reference or delete it; new explorations go to `design-exploration/`, which `design-direction` adds to `.gitignore`.

## 0.7.0 — 2026-10-30

- The hunt is smaller. Its goal is one `DESIGN.md`, and `.design/` is scratch you may delete once that exists; a later hunt for one piece works without it. `SKILL.md` drops from about 400 lines to under 200, and `quality.md` and `shots.md` become one `sources.md`. `proof.mjs` is gone: a prototype of the gaps is the proof. `moodboard.mjs` runs once, before the pick, as a grid of shots linked to their sources; `--leads`, `--also`, `--why`, `--count`, and `--imagery` are gone, and the pick is said in chat. A board card is six lines. A later hunt writes `.design/hunts/<slug>/board.md` with the same cards and its own moodboard.
- `tdd` from [Matt Pocock](https://github.com/mattpocock/skills) is in the default kit, under Code. It runs only when you ask for TDD, test-first, or red-green-refactor; `ponytail` stays the default for building and fixing. People who already ran `init`: install this version, then run `npx longbeard update`.
- The `AGENTS.md` block `init` and `update` write now matches the 0.6.0 hunt: the `DESIGN.md` ask is its own message, asked once more if they move on without answering. 0.6.0 shipped the older "ask once" line. Run `npx longbeard update` after installing this release.
- `update` tells an edit by content, not by file time. A fresh clone or a checkout no longer makes every skill look edited, so they refresh again. A lock written by 0.6.0 or earlier has no hash yet: if `update` lists a skill under "your edits" that you did not change, run `npx longbeard update --force` once.
- A direction can hold behaviour. **Read this** has a `behaviour:` line (how the page moves, pages, fades, or reveals, or `none`), `DESIGN.md` has a `## Behaviour` section, and `animate` reads it first.
- `capture.mjs` writes the format its `--out` extension names (PNG for `.png`). Given an image file, `--clip` is in the image's own pixels.
- `dribbble-cards.mjs` also drops code, video, and photo editors, AI assistants, dashboards, and SaaS.
- The hunt's first message has a redo line for when `DESIGN.md` already exists, and one progress line is allowed when the search ends.
- After the `DESIGN.md` question, the hunt offers a next step instead of stopping: prototype the gaps (the gaps are the prototype's brief), hunt one, or stop. For an app, the first round also asks for the main screens and how you move between them, and 6 references is offered as a quick look.
- `DESIGN.md` names ideas, not sources: no reference names, no `.design/` paths, and `leave` is written as ideas. It gains a "To see it working" line and a **Decisions** list. `design-md` may now record decisions you approve on a rendered prototype, with the reason, the date, and a contrast check for every new colour token.
- `.design/` stays out of git. The hunt adds it to `.gitignore` on its first write and says why: the screenshots are other people's work. If it was already committed, it tells you, and leaves untracking it to you.
- An `ownable` element is unconfirmed until it has been seen on a rendered screen. Faces are set at their real sizes before they are kept: the italic at quote size, and the figures where numbers sit.
- The router tells `design-taste-frontend` that with `DESIGN.md` it builds and checks, and does not art-direct; it also takes a prototype ask. A Figma file stays with `figma-design-to-code`. App screens use taste's app-screen rules and inspector, and a warning about something `DESIGN.md` decided is reported, not "fixed"; accessibility failures are still fixed. If you already have a `DESIGN.md`, move any reference names in it into ideas.

## 0.6.0 — 2026-10-23

- `update` refreshes a kit skill from the installed package. It used to hand every refresh to the skills CLI, which cannot fetch a skill that ships inside this package, so it printed "up to date" over files from an older release. Each line now says which versions moved (`design-reference-hunt 0.5.1 → 0.6.0`), `--force` always replaces, and the last line names the version you are running. Install the package first; `update` still does not fetch it.
- `design-reference-hunt` opens the moodboard **before** the pick, with eight to twelve screens rather than two, every picture linked to its source, captions under the shot, and whole references instead of a 320 px crop. New card fields carry it: `tagline:` (about six words, the only text on a tile), `faces:` (names only, so the type tile sets them for real), and `slot:` (a product page stays off the moodboard). After the pick it runs again with `--leads` and `--why`, so the lead's caption is the reason they gave, not a line written before they chose. `--imagery` is opt-in: a look with no pictures in it shows no imagery tiles, and an imagery count of 0 is a complete board.
- `design-reference-hunt` adapts a colour for a reason — contrast, the twist, our own pictures, our own brand — and keeps a generic sampled cream or ink as it is. Nudging a hex so it differs is a change nobody can see.
- `scripts/dribbble-cards.mjs` reads likes and views from the card's own stat elements and prints both columns. It used to take the first number in the card text, which could be the likes count, a digit from the title, or a full stop. A count it cannot read stays empty.
- `scripts/capture.mjs` takes a `file://` URL, so the moodboard can be checked before anyone is shown it, and `--clip-selector "<css>"` clips to an element's box instead of guessing coordinates for a type specimen.
- `design-reference-hunt` starts a whole look with a conversation, not a search. One round, every question skippable with "go": what they are into, pictures they already like (kept as `source: user` seeds that steer and rank the search), the subject and surface with the identity nouns from the name, whether it needs pictures at all, a checklist of sources with defaults for the surface, and how many references to see. It never asks a second round before searching.
- The search is smaller and cleaner. It queries for the form, not the word, and `dribbble-cards.mjs` drops a shared negative list (tees, CVs, worksheets, posters, logos) by slug and title before any thumbnail is fetched, then prints the noise rate. An app stops when two more queries add nothing, keeps the number they chose, and opens every shortlisted shot at full size. App hunts go to shipped screens first and mark each card `shipped: yes | concept`. Cards are short; only the lead and the `also` cards get the full fields.
- The moodboard is the narrowing step. It is built from what was found, before they answer, and the question is "which leads, which do you also like, which feel wrong, and why?". `--also` takes several cards, `--count` sets how many references show.
- **Read this** gains `ownable` (one concrete element from the project's own identity that the lead does not have), `gaps` (key screens with no strong reference, each offered as a later hunt after the persist answer) and `not shown` (what a concept lead never faced). `design-md` carries `ownable` and `gaps` into `DESIGN.md` and sends a board without `ownable` back.
- New `scripts/proof.mjs` writes `.design/proof.html` from **Read this**: paper and night side by side, a list row and a phone column, the faces at body size, contrast ratios, and text from the project's own README or product file. It is not the product. It runs before the persist ask and asks whether fewer font families would do.
- A redo of the whole look uses at least one source the last board did not, and one deliberately opposite query, to test whether the lead still wins.
- People who already ran `init` get all of this by installing this release, then running `npx longbeard update`.
